# ABI 4 补充验证：原生中文 OR、评分与验收检查器

2026-10-18。原 B0 的源码包、补丁、manifest、DLL/SO、头文件、三个 signed HAP 和 AND 证据保持不变；本次另存 B1 候选。累计 ABI 仍为 4，既有 C 布局、符号和 SDK 默认 QueryParser/AND 语义不变。未提交、推送、发布或移动 tag。

## 三项实际修复

1. **排名分析器曾假通过非同分颠倒。** B0 的 compare 只比较分数位到 ID 的集合，未比较分数组顺序。独立注入 high(3.0)、low(2.0) 倒置时，冻结旧检查器报告 non_tie_differences=0；修正后为 1。现在同时检查有序分数位序列、分数降序、共同 ID 分数/正文、连续名次及唯一 ID。六项独立测试覆盖非同分颠倒、错分/错正文、重复 ID/记录、非法名次、合法组内同分交换及合法/非法 Top100 边界替换。实际红→绿输出独立保存。没有增加分数容差。
2. **OR 负载暴露了 Count 开关改变评分路径。** 正式 B0 DLL 在同一默认索引上，372/500 查询的共同 ID 分数位有差异，最大 3 ULP，6 条查询的 ID 顺序也不同。该失败如实保留，未以“近似同分”放过。锁定源码中，单独 TopDocs 走 SortBySimilarityScore 的 pruning/Block-WAND 路径，组合 `(TopDocs, Count)` 走通用收集路径；BooleanWeight 对 term union 分别使用 block_wand 和 BufferedUnionScorer。候选改为始终执行原 TopDocs，仅显式请求总数时对**同一固定 Searcher**另做 Count 扫描。默认不计数路径不变，计数和页仍属于同一快照。新增 180 文档多词 OR 测试逐项核对 Count 开关前后的 ID 和 f32 分数位；另以全部 500 OR 查询核对，修正后差异为 0。额外扫描成本单列，未改上游或查询语法。
3. **拒绝非有限的实际返回分数。** 在结构化结果 materialize 与旧 JSON 结果物化处共用有限性检查。直接超大 boost，以及每个 boost 单独仍有限但组合溢出的查询，均明确返回 non-finite search score 错误，结果/JSON 输出槽清空。正常有限 boost 保留原数值和排名；字段排序仍不计算 BM25、score=0。Rust 回归覆盖 fast ID 和 stored-ID、v2/v3/旧 JSON、Count 开关及字段排序。实际 C99/C++11 consumer 以 create/reopen/readonly 三进程验证同样错误路径，随后正常查询仍成功；未交出的 Rust 结果由所有权自动释放。

生成规则、许可来源及完整复现步骤见 [OR_PROTOCOL.md](benchmarks/OR_PROTOCOL.md)。原 20,000 篇未预分词正文、500 条原查询和 qrels 的哈希保持不变。独立工具用锁定 jieba-rs 0.8.1 Default/HMM、小写重生成 tokens，与已冻结同源 queries.tokens.tsv 逐字节一致；共 2,819 token、保序去重后 2,794 个词项。每个词项正确转义为引号字面量，以显式 OR 连接，AST 往返和六组元字符测试通过。

8 个上下文 HMM 词项独立重分析时会拆分，例如“图元”→“图 / 元”；全部保留并写审计 TSV，遵循公开 QueryParser 的原生分词/短语语义，不使用私有精确 TermQuery。正文仍由各公共 SDK 的原生 Jieba 建索引，没有使用 whitespace 或旧诊断检索入口。

500 查询全部合法，零命中率为 **0**。ABI2 对照与候选的默认词典保持一致，排名、分数位和返回正文全部一致；候选 Count on/off、ID/body 的排名和分数位一致，ID/body 的精确总数逐查询一致。正文模式对每个实际返回正文逐字节核对冻结原文。全部 24 个 profile 的 36,000 条查询样本还单独用修正后的检查器复核，错误、非同分差异、正文差异均为 0；自定义词典仅与自身重复结果核对，不宣称与默认语义相同。

## 生产回归与候选对应

- Rust release 最终 **18 passed / 0 failed**，保留所有既有有效断言；新增多词 OR Count 一致性及非有限评分测试。
- C99/C++11 supplement consumer 严格编译，各 create/reopen/readonly 三独立进程通过，复用 A、B0 验收并补有限评分边界。
- 原 ABI1/2/A consumer 二进制仅换新 DLL 回归通过；真实 A/旧/新索引的只读字节与 mtime 不变。
- 正式 release DLL 的独立黑盒：只损坏新建私有索引副本各 `.store` 压缩块开头 8 字节，保留长度/footer。新句柄的 fast ID+Count 返回 8 个唯一 ID，而正文投影明确返回 LZ4 的 literal 越界错误、输出槽为空。只读全程文件不变；未使用 cfg(test) 计数器冒充证明。
- OHOS release、实际 C/C++ 链接、新功能验证与两个 OR 基准 signed HAP 构建通过。Raw SO 与 HAP 内库以 SDK strip-all 变换精确对应；签名工程/材料、语料、索引与二进制不进入审阅源码包。

新的源码、头文件、DLL/SO、HAP、工具、输入/派生查询与检查输出哈希见补充候选 manifest。新建交付使用 B1/OR 准确名称及独立校验清单；原 B0、A 和带 v2 名称的旧入口不再覆盖。
