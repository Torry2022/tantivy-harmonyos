# 同配置 Jieba 共享验证（2026-10-18）

本轮仅减少 v3 同配置不可变词典的重复构造。ABI 仍为 4；没有改变 C 布局/符号、索引格式、元数据、默认分词/HMM/小写流程、排名、分页、Count 或查询实现。v2 原有静态默认词典路径保留。此前 A/B1 文档和设备证据对应其冻结产物，本记录不改写历史。

## 实现与生命周期

`src/tokenizer.rs` 使用专用 `Mutex<Vec<Weak<ConfiguredJieba>>>`。词典配置与 Jieba 位于同一个 Arc 管理的对象中；判等比较完整 mode、有序词条、词频，不使用指纹代替配置。默认和完全相同的自定义配置可共享，不同配置保持隔离。冷构造在池锁内完成，添加词条结束后才发布；分词仅借用不可变 Jieba，查询不获取池锁。

池没有自定义词典的永久强引用。最后一个使用者释放后，对象及配置 Vec/String、Jieba 堆随 Arc 析构；残余 Weak 控制块不保留这些内容。下次池访问清理过期弱项。注册的 Tantivy analyzer 持有强引用并可克隆，直至句柄及其使用者释放；无新增公开缓存选项或一般缓存框架。

## 宿主检查

- 四项结构测试：默认/两个自定义词典隔离，相同配置 Arc 指针一致，频率或条目顺序不同不混用；并发首次构造；六个实际只读句柄注册并发打开；最后 writer/reader/Arc 释放后 Weak 无法升级，重开取得新实例且旧弱项清除。Send+Sync 由类型检查验证。
- 完整 Rust 回归 22 passed；之后仅将并发测试屏障移到 unwrap 前以避免失败线程导致测试挂起，最终结构测试 4 passed。生产实现未在两次检查之间改变。
- 新 release DLL 的 C99/C++11 consumer 各 create/reopen/readonly 三进程通过；未修改的 ABI1、ABI2 C/C++、ABI3 A consumer 通过。实际旧/A/fast-ID 索引只读字节和 mtime 不变；故意破坏私有 docstore 的 fast ID+Count 仍通过、正文明确报 LZ4 错误。
- Windows 与 OHOS release、两个独立签名 HAP 构建通过；公共头文件仅修正 ABI4 返回值/结果释放/fast-ID 注释，不改布局。

保留工具设置失败：最初 C++ 编译的 `-x c++` 误作用 DLL 输入，修正 `-x none` 后通过；旧 C++ consumer 初次运行缺少 pinned LLVM-MinGW runtime PATH，stdout/stderr 为空且未创建索引，首次未记录返回码，补齐既有环境后同一二进制通过；旧 ABI1 runner 漏必需 create/read 参数返回 2，按原用法修正后通过。它们没有被归因于 OS5 或隐去，也没有通过重试 SDK 写入吞错。
